Where the events go, what the agent sees, and how to prove it works

The problem: a scalable system takes a very high throughput of heterogeneous events, promotes the few that matter to an AI harness immediately, folds the rest into something an agent can use later — and has to be evaluated honestly. What the literature says about each open question, and what it does not say.

Q0

Is it the engine's job to store events and keep aggregated, agent-ready state — and when should that happen?

Yes. Every production memory system writes state incrementally per event and reads it cheaply at inference; nobody rebuilds state from raw logs on the hot path. Keep the raw log, maintain per-entity state, give the agent bounded tools back into the log. Aggregate at per-entity window close; compact periodically; pin the facts that must not be summarised away.

Q1

Which events go to the fast lane, which to batch, and how does that decision work?

Define urgency as expected cost of delay (Horvitz), not as a label. The fast lane is a budget (~1–5 %), the classifier a ranker under it. Two static layers: a per-source rules floor, then a per-entity deviation score with an absolute-volume floor. Expect modest ranking quality (F1 ≈ 0.6–0.7 in comparable settings); the budget, not the model, is the safety control.

Q2

What is the best context to give the agent for a processing run?

The smallest high-signal set, ordered for primacy/recency and cache stability: stable prefix → entity state → events as one block → compact action log → instruction. Fast runs ≤ ~10k tokens with just-in-time tools; batch runs larger but consolidated, never replayed turn by turn. Exclude superseded material by default — it is a measured distractor.

Q3

What does "processing" mean for an AI harness on either lane?

A typed run: (state@version, events[], action_log) → state_delta[] + actions[]. Batch runs emit deltas (ADD / UPDATE / SUPERSEDE / NOOP, each citing evidence events) and no external actions; fast runs emit at most one idempotent action plus a minimal delta. The harness, not the model, validates and applies.

Q4

How do we evaluate the whole thing?

Four independent studies with ground truth that does not require urgency labels: E1 routing under a budget (injected anomalies + weakly-supervised labels; VUS-PR, affiliation, precision@budget), E2 state fidelity against facts re-derivable from the log ("status as of T", links, touched files), E3 action quality with the context varied and the agent fixed, against real human actions, E4 open-loop throughput and tail latency under bursts with the LLM mocked, plus agent-runs per 1,000 events.

Numbers in brackets link to the unified reference list. Items the researchers could not fully verify are marked there.

Question 0 · responsibility and timingIs storing and aggregating events the context engine's job?

Verdict

Yes. The engine should keep the raw event log as source of truth and maintain precomputed per-entity state from it; the agent gets that state plus bounded tools back into the log. The batch lane is the write path that builds state; the fast lane is the read path that acts on it. This is what every deployed memory system does, what Confluent's product does with SQL, and what the streaming literature calls a materialized view over a changelog.

What the memory systems actually do

Every production-oriented agent memory system writes state incrementally per event or message and reads it cheaply at query time; none reconstructs state from a raw log at inference. MemGPT keeps a fixed working context plus a FIFO tail and, at a capacity threshold, folds evicted messages into a recursive summary while keeping them retrievable by tool call[1]. Mem0 extracts facts on every message pair, reconciles each against existing memories with ADD/UPDATE/DELETE/NOOP, and refreshes a rolling summary asynchronously off the hot path — reporting 91 % lower p95 latency and >90 % fewer tokens than full-context, at a measured cost of about six points of judged accuracy[2]. Zep/Graphiti ingests into a bi-temporal graph where contradicted facts are invalidated rather than deleted, and needs periodic community refreshes because incremental updates drift[3]. A-MEM lets each new memory trigger rewrites of older ones[4]; Generative Agents keep the raw stream and fire reflection when the summed importance of recent events crosses a threshold[5]. Index-time aggregation in RAG tells the same story: GraphRAG pregenerates community summaries[7], RAPTOR builds summary trees[8], and HippoRAG's offline graph plus one retrieval step matches iterative agentic retrieval at 10–30× lower cost[9]. Sleep-time compute quantifies the principle: pre-thinking over a context before queries arrive gives ~5× lower test-time compute at equal accuracy, and the benefit grows with query predictability[13].

The 2025 memory survey draws the line the thesis needs: memory "dynamically forms, consolidates, and forgets", whereas RAG re-retrieves from a static store[11]. Karpathy's LLM-wiki pattern says the same thing operationally — with RAG "the LLM is rediscovering knowledge from scratch on every question. There's no accumulation" — and structures it as immutable raw sources, an LLM-maintained wiki, and a periodic lint pass[18].

Industry has converged on the same shape, without the LLM

Confluent's Real-Time Context Engine "continuously materializes enriched enterprise data sets into a fast, in-memory cache" via Flink and serves them over MCP; its stated argument against query-time raw access is that raw data is "littered with cryptic codes and IDs no human or AI can interpret" and that querying source systems at inference exposes them to load[20]. The May 2026 GA describes the data model plainly: keyed row lookup by primary key, now with filters and ranges[21]. Materialize frames the same idea as "an always-current model of relevant business entities" delivered by incremental view maintenance[25][26]. Both are fixed-schema SQL views; neither has an LLM maintain the state.

The theory: a table is a folded stream

Stream–table duality says a table is the aggregation of a changelog and a stream is the changelog of a table; a KTable is "a continuously updated materialized view"[40]. Kreps' Kappa argument gives the disposability property: keep the log, derive tables with one stream job, replay when logic changes[39]. The Dataflow model supplies the vocabulary for when: windowing decides where in event time, triggers decide when to emit, and refinement mode (discarding / accumulating / accumulating-and-retracting) decides how repeated emissions relate; session windows are per-key, unaligned, gap-merged[41]. Flink implements exactly this with keyed session windows, event-time triggers and allowed lateness[42].

The hybrid "state as of last fold + unfolded tail" has direct precedent: it is MemGPT's recursive summary plus FIFO queue[1] and Mem0's asynchronous summary plus last-m messages[2].

What the literature does not support

  • Treating the materialized state as sufficient. Mem0 loses ~6 accuracy points versus reading everything[2]; compaction studies from 2026 show summaries silently drop constraints (violations 0 % → 30 %, up to 59 % for some models) unless critical facts are pinned outside the lossy summary[62], destroy causal structure[63], and weaken recent-interaction influence[65]. Hence the raw log must remain reachable through tools.
  • Synchronous compaction on the hot path. Slipstream shows synchronous summarisation "silently introduces errors because the summarizer lacks visibility into what information the agent will need downstream"; asynchronous, validated compaction is +8.8 pp accuracy and up to 39.7 % lower latency[64].
  • Incremental-only maintenance forever. Graphiti and the wiki pattern both require a periodic full pass to correct drift[3][18]; a 12-system study finds "localized maintenance is more cost-efficient than global reorganization", which argues for per-entity folds with rare global passes[17].
  • Unbounded agentic retrieval. It is more accurate (Search-R1 +20–41 % over single-shot RAG) but multiplies tokens 4–15×[56]; tools should be keyed lookups and time-range scans, not open search.
  • Dumping raw histories into context. Position and length effects degrade accuracy non-uniformly even for long-context models[45][48].

The gap you can fill. There is no controlled study comparing LLM-maintained per-entity state against agent-driven warehouse queries on a heterogeneous enterprise event stream. The nearest evidence is Letta's file-system agent beating Mem0's graph on LoCoMo (74.0 vs 68.5 with GPT-4o-mini)[14] and a July 2026 study finding that filesystem-memory organisation "erodes for all but the strongest management agent"[16].

Question 1 · routingWhich events go to the fast lane, and how does the decision work?

Verdict

Route by expected cost of delay, under a fixed budget. A per-source rules floor captures the known-costly types; a per-entity deviation score with an absolute-volume floor captures the unexpected. Ground truth for "urgent" does not exist and priority fields are too noisy to stand in for it, so the budget — not classifier accuracy — is the primary safety control.

The theory behind "cost of delay"

The formal antecedent is Horvitz, Jacobs and Hovel's Attention-Sensitive Alerting: a decision-theoretic mediator that balances "the context-sensitive costs of deferring alerts with the cost of interruption", prioritising by the expected cost of delayed action rather than by topic[75]. The mixed-initiative principles make it a threshold decision: act only when the probability of need exceeds a threshold set by the relative costs of false action and inaction[76]. Bounded deferral is the batch lane: defer non-urgent items for a bounded time "in return for bounded delays in receiving information"[77]. Interruption-cost studies justify scarcity — badly timed interruptions raise frustration and reaction time; deferring to breakpoints reduces both[78][79]. Reinertsen supplies the economic framing of queue prioritisation by cost of delay[80]. On the operations side, the SRE book requires a page to be "urgent, actionable, and actively or imminently user-visible" and warns fatigue sets in after a few pages a day[81]; the SRE Workbook's multi-window, multi-burn-rate alert is the best-engineered budgeted-urgency scheme in practice and a direct template for the second layer[82]. No peer-reviewed paper literally ranks operational alerts by cost of delay; say so rather than citing blog posts.

Layer 1 — the rules floor

DAGOR at WeChat is the closest industrial analogue to a compound priority: a business priority by action type plus a per-user priority from a rotating hash, with the admission level adjusted in ~5 % steps and propagated upstream[96]. Aurora's load shedding distinguishes random from semantic (value-based) drops[100] — the rules floor is a semantic admitter in that vocabulary. Kafka has no native priority; Confluent's guidance and KIP-349 explain why separate topics are the pattern and why strict priority starves the lower lane, which a fixed budget avoids[101][102].

Layer 2 — per-entity deviation

Cloudflare's production alerting fires at |z| > 3.5 over a 5-minute window against the past 4 hours, but only with more than 200 events — because low-volume entities make "any non-zero spike calculate as infinite standard deviations away"[83][84]. Its bot platform fits per-site baselines with HBOS for linear-time scoring[85], and Radar's outage detector adds a magnitude floor and two thresholds (sustained vs point)[86]. HBOS itself "performs poor on local outlier problems"[87], and ECOD/COPOD are likewise global-tail methods[91], so scoring must be per entity or on entity-normalised features — Chandola et al.'s contextual-anomaly distinction, with entity and time as the context attributes[95]. Use MAD over standard deviation because the baseline window contains the spikes being detected[94]. Streaming detectors with bounded false-positive rates are attractive for a budgeted lane: ADWIN adapts its window with guarantees on both error rates[92]; Half-Space Trees and RRCF are the standard constant-memory streaming scorers[88][89].

How good can it be, and why labels will not tell you

Classical severity/priority prediction reaches precision/recall around 0.65–0.75 on Mozilla/Eclipse[107]; DRONE's multi-factor model improves relative F-measure substantially but absolute performance on rare high-priority classes stays modest[106]. Escalation prediction at IBM reached 79.9 % recall on 2.5 M tickets[108]; TickIt deploys LLM escalation at ByteDance without published accuracy[109]. The decisive caveat is label noise: about 51 % of duplicate bug reports carry inconsistent human-assigned severity even though they describe the same problem[103]; 33.8 % of "bug" reports are misclassified[104]; and the linked subset of fixes is biased by severity[105]. Proactive-agent work reports F1 ≈ 0.66 for the "should I act now" decision[110] and 50–65 % zero-shot timing accuracy, +11.8 points with memory[111]. Most sobering: a failure-predicting critic with AUROC 0.94 still hurt outcomes when used to trigger interventions — ranking quality does not validate a fast lane; downstream harm must be measured[112].

Known failure modes to design around

  • Degenerate z-scores on low-volume entities → absolute floor[83].
  • Global detectors miss entity-relative anomalies → per-entity or entity-normalised scoring[87][95].
  • Baseline poisoning by bursts and slow ramps → MAD, capped adaptation, multi-window confirmation[94][82].
  • Self-amplification: a burst is the anomaly, so the fast lane fills exactly when load peaks → the budget guard plus one deduped "situation" envelope per window; the overload-control analogues are Breakwater's delay-keyed admission[97], SEDA's per-stage controllers[98] and brownout's optional-work shedding[99].
  • Starvation of the batch lane under strict priority → fixed budget, not strict precedence[102].

Question 2 · the envelopeWhat is the best context to give the agent?

Verdict

"The smallest set of high-signal tokens that maximize the likelihood of the desired outcome"[51], ordered for primacy/recency and prefix stability, with just-in-time tools for anything beyond it. Give the agent lexical hooks (IDs, stable headings) — state that must be found by meaning degrades with length far faster than state found by string match.

What practitioners converge on

Anthropic recommends lightweight identifiers loaded just-in-time, compaction that maximises recall then trims, structured note-taking to persistent files, and sub-agents that return 1–2K-token summaries[51]; its harness guidance adds a progress file plus git checkpoints, read first, verify before marking done[58]; its tool guidance says return semantically meaningful IDs, paginate, and offer concise/detailed formats[57]. Manus reports that KV-cache hit rate is "the single most important metric" for production agents — keep the prefix stable and the context append-only, mask tools rather than remove them, use the filesystem as restorable compression (keep the path, drop the content), and keep failed actions visible[53]. LangChain's write/select/compress/isolate taxonomy warns summarisation is risky "when specific events or decisions need to be captured"[54]. Claude Code's own memory docs cap files at ~200 lines because "longer files consume more context and reduce adherence"[60].

Question 3 · the contractWhat does "processing" mean for an AI harness?

Verdict

A run is a function over versioned inputs with a schema-enforced output. Batch runs produce state deltas; fast runs produce at most one idempotent external action plus a minimal delta. Defining it this way is what makes runs evaluable at the operation level and replayable from the log.

Why a typed contract

ReAct established the action-observation primitive[67], but the strongest evidence on interface design is SWE-agent's ablations: linting guardrails +3 pp, removing the edit command −7.7 pp, summarised search results +6 pp over iterative browsing, a 100-line window beating both 30 lines and whole files, collapsing all but the last five observations +3 pp — overall 18 % vs 11 % for a raw shell[68]. The lesson: few, compact, consolidated actions; concise feedback; validation at the boundary. Both major APIs now enforce schema-valid output and strict tool arguments[70], so the contract can be enforced by the harness rather than by prompting. AgentBoard's argument for a fine-grained progress rate over binary success[69] applies directly: define per-run sub-goals (facts extracted, conflicts resolved, actions emitted).

The memory-write operation, state of the art

The surveys formalise write / manage / read operations[10][11]. The most operational write definition is Mem0's: extract candidates from summary + recent window + current input, retrieve the top-10 similar memories, then choose ADD / UPDATE / DELETE / NOOP, with contradiction handled by DELETE[2]. MemGPT makes the write an explicit tool call[1]; A-MEM lets new memories rewrite old attributes[4]; Graphiti invalidates rather than deletes[3]; the wiki pattern keeps raw sources immutable and flags contradictions[18]. A tombstone log (superseded.md) sits in the append-only camp and is defensible on auditability — provided it is not loaded by default[48].

            state: { overview, timeline_tail, facts[], superseded_index[] },

            budget: { max_tokens, max_tool_calls } }

Tools     { read_state, search_facts, recent_events,
            act(action, idempotency_key)          // FAST only }

            state_delta[]: { op: ADD | UPDATE | SUPERSEDE | NOOP,

                             evidence_event_ids[], confidence },
            actions[]:     { type, params, idempotency_key,
                             precondition, postcondition },
            open_questions[], summary (≤ 300 tokens) }
  • Every delta cites evidence_event_ids — this is what makes E2 gradable per operation and lets a reviewer trace any fact to the log[18].
  • The harness applies the delta after a linter-style validator (schema, referenced IDs exist, no duplicate keys); rejected deltas return concise errors for one retry[68].
  • Idempotency. (entity_id, event_id) processed-marks are committed atomically with the delta; the act tool dedupes on key and verifies postconditions before any retry — verified tool calls significantly reduce duplicate actions at equal task success[73]. At-least-once delivery plus non-deterministic inference means the idempotency check must run before the LLM does[74].
  • The agent's own history is a distinct memory type. Reflexion's episodic buffer[71] and the position that episodic memory is "the missing piece" for long-term agents[72] both model prior actions separately from world facts; keep it as a compact action log, not a transcript[55].
  • Assume interruption. Anthropic's memory-tool protocol ("your context window might be reset at any moment… record progress") is the practical form of the same requirement[61].

Question 4 · evaluationHow do we evaluate the whole problem?

Verdict

Four independent studies, each with ground truth that does not depend on anyone labelling "urgent", each paired on the same replayed stream. The unifying quantity is cost of delay: E1 asks whether high-cost events are admitted, E4 whether they are delivered fast, E2 whether the state they need exists, E3 whether that state changes the outcome.

E1 — Routing: are the right events in the budget?

Ground truth
(a) Injected urgent events synthesised into real replays, controlling point difficulty, relative frequency, clusteredness and feature relevance[121] and avoiding the triviality / unrealistic-density / mislabelling flaws documented for existing benchmarks[115][118] — TSB-UAD builds 10,828 of 13,766 series this way[116]. (b) Weak labels fused with a Snorkel-style label model over declared priority, keywords, reporter role, comment bursts and later outcomes (escalated, fixed within 24 h), with each source's accuracy estimated rather than assumed[113] — priority is explicitly noisy[103][104][105].
Metrics
precision@budget and recall@budget at 1 / 2 / 5 %; VUS-PR as the threshold-free headline[117]; affiliation precision/recall for per-incident lateness[119]; NAB early-detection score under the reward-low-FN profile[114]; median and p95 detection delay. Never point-adjusted F1 — it makes random scores look state-of-the-art[120].
Baselines
random-at-budget, rules-only, recency-only, global (non-entity) z-score, always-fast. Report per source, never pooled[115]. Rules will win on declared labels by construction; the deviation layer is evaluated on what rules miss.
Beyond ranking
Because an accurate trigger can still cause harm[112], pair E1 with E3: for fast-routed events, does acting now versus at window close change the outcome?

E2 — State fidelity: does the batch lane build correct context?

Ground truth
Facts re-derivable from the log itself. From the Public Jira dataset's 32 M changelog entries: "status / assignee / priority of ticket N as of T", duplicate-of and blocks links[155]. From Git/GitHub: files touched by the fixing commit, ticket↔commit links from the mandated key in commit messages[132][134].
Probe types
Mirror LongMemEval's five abilities — extraction, multi-session reasoning, temporal reasoning, knowledge update, abstention[12] — with TimeQA-style time-conditioned questions[126][127]. The knowledge-update and temporal categories are the direct analogue of supersession correctness; Zep argues these are the enterprise-relevant tests[3].
Grading
Decompose gold into atomic claims; RAGAS context precision / recall at the claim level[128]; for file sets, ContextBench's context recall / precision / efficiency[125] and Agentless's superset rule[132]; token-F1 with normalisation for short answers as in LoCoMo[122]. Add staleness (event time → first snapshot reflecting it), tokens per entity, and tool-call rate per run (a high rate means the state is bad). MemoryAgentBench's selective forgetting and MemBench's efficiency/capacity axes are the secondary dimensions[124][123].
Baselines
raw last-N events; BM25 and embedding retrieval over raw events (same read agent, same budget); an uncurated dump (one file per event). Sanity floors: retrieve-everything and retrieve-nothing.

E3 — Action quality: does the context change what the agent does?

Design
Fixed agent and prompt; vary only the context: {none, raw last-N, curated state, curated state + tools}. This is the standard fixed-agent ablation used by Mem0, Zep and SWE-agent[2][3][68].
Gold actions
Software: assignee@k precision/recall[129], component prediction, duplicate recall-rate@k / MAP[131][130], file-localisation superset accuracy[132], and — where a grader exists — SWE-bench-style FAIL_TO_PASS on a small SWE-bench-Live slice[133][134]. Support: gold human replies (Customer Support on Twitter, TWEETSUMM; or an owned helpdesk corpus)[135][136]; τ-bench's state-comparison and pass^k for reliability[137][138].
Judges
Only for free-text replies, position-swapped, from a different model family, with Cohen's κ against a ~200-item human subset — judges show position, verbosity and leniency bias, and percent-agreement hides scoring gaps[139][140][141]. This is why SWE-bench, Agentless and τ-bench ground success in executable or database state[133][132][137].

E4 — System: throughput and fast-lane latency under burst

Method
Open-loop replay at constant rates with latency measured from the intended send time — the coordinated-omission discipline, where the naïve p99 can be ~200× too optimistic[146]. Event-time latency and sustainable throughput as defined by Karimov et al.[142]; Theodolite's resource-demand metric ("minimal resources to meet the SLO at load l") swept over event rate and entity cardinality[143][144]; OMB-style p50/p99/p99.9 reporting[145]. Run the pipeline with the LLM mocked so the broker and engine are what is measured — the Yahoo benchmark's mistake was measuring Redis[147].
Bursts
Characterise the real streams with the burstiness parameter B and its finite-size correction, and generate replays with matched B[148][149]. Include a benign flash crowd (volume up, mix stable → should stay batch) and an anomalous burst (mix shifts → one situation envelope). Plot fast-lane admission rate and urgent-event SLO compliance on one time axis to expose self-amplification.
Economics
With the real harness: agent-runs and tokens per 1,000 events per lane, following LLM-serving reporting norms[150]. This is the number that justifies the batch lane: cost scales with windows, not events.

Statistics for all four

  • Everything is paired on the same replayed stream: paired differences with clustered standard errors (probes sharing an entity are not independent) and bootstrap CIs; power analysis before fixing probe counts[151][153].
  • McNemar for binary correctness between two conditions[152].
  • Pre-register one primary metric per study; Holm–Bonferroni across secondaries.
  • The builder is nondeterministic: ≥ 3 seeds per condition, report pass^k and run-to-run variance of the state itself[137][154].
  • Label-noise robustness: jitter injected timestamps and flip a fraction of weak labels; show E1 rankings are stable.

PositionPrior art and the gap

Each component of the design has a neighbour that must be cited; the intersection does not exist. "Open source" alone is not a gap — Flink Agents, Graphiti, Letta, Cognee and Supermemory are open source[24][3][15][32][33]. Per-entity precomputed state is done with SQL by Confluent and Materialize[21][25] and with LLM-extracted graphs by Graphiti[3]. Event-triggered agents exist in Flink Agents (FLIP-531: "system-triggered", event-driven microservices with state and replayability)[23][24], Confluent Streaming Agents[22] and StreamNative Orca[28] — but all trigger on developer-defined conditions, not an urgency budget. AIOps triage agents (RCACopilot, COMET, Datadog Bits, incident.io) key off pre-labelled alerts and precompute topology/runbooks/history[157][158][160][161]; incident.io's backtesting against the eventually-known resolution is the nearest precedent for derivable-ground-truth evaluation[161]. Support vendors report self-defined resolution rates with no comparable method[162]; Customer 360 is the fixed-schema, identity-resolution version of per-entity state[163].

Gap statement

No prior work (a) has an agent harness fold windowed, heterogeneous business events keyed by entity into a human-readable versioned state document with the stream as the trigger; (b) feeds an agent through a label-free, explicitly budgeted urgency lane; or (c) evaluates the fidelity of LLM-maintained per-entity state against ground truth re-derived from the same log. Each part has a neighbour; the intersection, in one open-source system with that evaluation, is the contribution.

ChecklistPitfalls the literature warns about

  1. Point-adjusted F1 inflates anomaly-detection scores to the point where random beats real[120].
  2. Trivial or dense injected anomalies, and pooled reporting across series[115].
  3. Priority/severity as ground truth: 33.8 % misclassified reports; 51 % inconsistent severities on duplicates[104][103].
  4. Ticket↔commit link bias: the linked subset is not representative[105].
  5. A good trigger can still cause harm — measure downstream effect, not just ranking[112].
  6. Judge position, verbosity and leniency bias; percent-agreement hides gaps — use κ[139][140][141].
  7. Coordinated omission in latency measurement[146]; measuring the broker instead of the engine[147].
  8. Single-run pass@1 hiding run-to-run variance of a nondeterministic builder[137][154].
  9. Recall-over-precision context bloat — agents over-retrieve[125]; it is the direct cause of token waste.
  10. Unclustered standard errors when probes share an entity[151].
  11. Compaction silently dropping constraints and causal structure[62][63]; synchronous compaction on the hot path[64].
  12. Filesystem-memory organisation eroding under weaker management agents[16] — report state health over time, not only at the end.
